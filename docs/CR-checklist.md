# 代码审查（CR）自查清单 —— Navidrome 自建分支

> 用法：每次提交前逐条自查并在 PR/提交说明中标注；带 ★ 的为必查项，未通过不得提交。

## 一、功能与需求 ★

- [ ] 改动能对应到 PRD 中的需求编号（`docs/BaiduSync-PRD.md`）
- [ ] 验收标准（Given-When-Then）逐条自测通过，证据已记录（日志/截图/命令输出）
- [ ] 边界覆盖：空输入、超长、路径不存在、无权限、并发/重复触发
- [ ] 影响面检查：是否波及关联模块（前端菜单/路由/i18n、后端路由鉴权、助手动作白名单、部署脚本）

## 二、编码规范 ★

- [ ] 新增/修改代码有**中文注释**；复杂逻辑注释「为什么」
- [ ] 函数 ≤ 50 行、嵌套 ≤ 3 层；`handler → helper/client` 单向调用
- [ ] `gofmt -l` 无输出、`go vet` 0 问题；前端 `eslint` 0 error
- [ ] 无调试残留（`fmt.Println`/`console.log`）、无硬编码敏感信息
- [ ] 文件行尾符合项目约定（`.go` 用 LF；`conf/configuration.go` 保持 CRLF 不整文件改写）

## 三、安全 ★

- [ ] 外部输入已校验（类型/范围/格式/路径）
- [ ] 路径操作有白名单或包含性校验（`ensureWithin`），拒绝 `..`
- [ ] 特权操作走 root 助手，Web 进程不接触百度凭据
- [ ] 敏感信息不出现在命令行、日志、对话；凭据文件用后 shred
- [ ] 破坏性操作有软删/干跑（`dryRun`）兜底与审计日志

## 四、错误处理与可观测 ★

- [ ] 失败必须显式暴露（禁止「退出码 0 + 空输出」被当作成功）
- [ ] 错误信息可定位（含关键上下文，截断超长内容）
- [ ] 日志分级与保留策略合理（按天分文件、过滤噪音、自动清理）
- [ ] 进度/状态数字来自**本次运行**，可复算

## 五、测试 ★

- [ ] 受影响模块有单测（`go test ./tools/nd-helper/...` 全绿）
- [ ] 编译通过：`90-build-deploy.ps1`（含前端构建 + zig 交叉编译）
- [ ] 部署后实测：核心流程 + 至少 1 个边界场景
- [ ] 回归检查：既有功能未被破坏（播放/扫描/登录/权限）

## 六、交付与变更管理 ★

- [ ] `CHANGELOG.md` 已按日期 + 编号更新
- [ ] 提交信息为中文、能说明「为什么」
- [ ] 未提交编译产物/临时脚本（`dist/`、`*.run.sh`、二进制）
- [ ] 生产部署需用户通知，回滚方案可用（官方二进制备份 + 一条命令）

## 七、本次自建功能的专项注意点

- [ ] 同步范围仍钉死在 `remoteRoot/localRoot`（`lockPaths` 生效），未放宽
- [ ] 下载 `--saveto` 指向**对应本地子目录**（不得落到 `music/` 外层）
- [ ] 新增排除目录/扩展名白名单时同步更新单测
- [ ] 进度分母=本轮计划数、分子=本轮去重的完成数
- [ ] 助手动作白名单未新增未审计的破坏性动作
