# 本地重复歌曲检测与一键清理 —— 技术方案

> 日期：2026-09-28　状态：待用户评审　来源：用户需求「检测本地重复歌曲 + 一键清理」

## 一、需求

音乐库存在重复歌曲（同一份文件存了两份），需要提供**检测**与**一键清理**能力，
避免逐首手动删除。用户已确认：**本地与网盘（云端）都要删**。

## 二、现状（生产实测，2026-09-28）

| 维度 | 组数 |
| --- | --- |
| 同「艺人+歌名」（归一化后） | 63 |
| 其中时长也一致（≤2s） | 63 |
| 文件大小 + 内容完全相同 | 62 |

- 244 首中约 **63 首为冗余副本**，清理后约 181 首
- 重复形态统一：同一份文件同时存在于
  - `歌手/专辑/歌名 - 歌手.mp3`（三级目录，结构规整）
  - `歌名 - 歌手.mp3`（music **根级**，散装）
- 两侧 size / duration 完全一致（如 4174166 字节 / 240.93 秒）→ **同一份文件的两份拷贝**，非不同音质

## 三、方案

### 3.1 检测（新增）

`GET /api/duplicates`（adminOnly）

1. 分组键 = `normalize(artist) + normalize(title)`（NFKC、去空白与零宽字符、小写）
2. 组内**内容指纹** = `size + 头部 1MB MD5 + 尾部 1MB MD5`
   （不做全量 MD5：大库全量哈希 IO 代价过高，头+尾+大小已足够区分）
3. 组内时长聚类（差 ≤ 3 秒）：时长差异大的同组项标记 `sameContent=false`（视为不同版本）

返回：组列表（每组含 `id / path / size / bitrate / duration / format / depth`、
推荐保留项 `keepId`、推荐删除项）+ 统计（扫描数、组数、冗余数）。

### 3.2 保留策略

组内**内容相同时**只留一份，优先级（依次比较）：
1. 目录层级更深（`歌手/专辑/` 里的优先于根级散装）
2. 码率更高
3. 文件更大
4. 路径字典序（保证结果稳定可复现）

组内**内容不同**时：**不自动删**，前端提示「可能是不同版本」，需用户手动勾选。

### 3.3 清理（复用现有通道，不新增写操作）

复用 `POST /api/mediaops/delete`：
- `ids` = 各组「非保留项」的 media_file id
- `scope = {library:true, local:true, remote:true}`（三处一起清）
- **固定先 `dryRun:true`** 拿清单 → 前端确认框展示 → 确认后才真正执行
- 软删（配置 `SoftDelete=true` 时强制）：本地 → `trash/files/`、网盘 → `/_deleted/`，**均可恢复**
- 网盘路径由库记录自动映射（`LocalRoot` → `RemoteRoot`），前端不传路径，避免伪造

### 3.4 安全措施

1. **每组至少保留一份**：服务端二次校验，若某组所有项都在删除列表 → 拒绝该组
2. **必须预览**：一键清理固定先 dryRun
3. **软删优先**：配置为软删时硬删请求被强制改回
4. **路径越界校验**：沿用 `ensureWithin` / `relTo`
5. **审计日志**：记录操作人、组数、删除项数、结果
6. 库根与助手 `localRoot` 不一致时**不做**网盘映射（宁可跳过，不误删网盘文件）

### 3.5 前端

- 侧边栏「歌曲」下方新增「**重复歌曲**」入口（`/duplicates`，仅管理员）
- 顶部：`重新检测` + `一键清理重复项（N 首）`
- 列表：按组展示，组内标注「保留 / 待删除」，支持**手动换选**保留项
- 清理流程：点击 → dryRun 清单 → 确认对话框（展示将删路径 + 提示"本地与网盘同时软删，可在回收站恢复"）
  → 执行 → 结果（本地 / 网盘 / 库记录各自成功数）

## 四、风险与应对

| 风险 | 应对 |
| --- | --- |
| 误判不同版本为重复 | 要求时长接近；内容不同则不自动删；必须预览确认 |
| 误删网盘文件 | 走网盘软删 `/_deleted/`；路径映射失败则跳过该项 |
| 删完下次同步又回来 | 本次**三处一起清**（含网盘），从根上消除 |
| 大库检测慢 | 只读文件头尾各 1MB，不全量哈希；接口带超时 |

## 五、验收标准

1. 检测结果与本次实测基线一致（63 组 / 约 63 个冗余项）
2. 一键清理后：每组只保留推荐项，其余在**本地 + 网盘 + 库记录**三处均删除
3. 清理后重新检测 → 重复组数为 **0**
4. 回收站可见被删项，可一键恢复
5. 每组至少保留一份（服务端校验生效）
6. 非管理员无法访问接口与页面
